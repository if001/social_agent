# 060: Time・External・System Eventを本番で投入する入口を揃える

## Background

DomainとRouterは各Event kindを受けられるが、本番の継続起動で自動生成されるのはSchedulerの`internal` Event、外部入口はDiscord/Queueメッセージが中心である。概念設計 §23と実装設計 §8、§25が挙げる時刻経過、外部サービス変化、起動・停止・権限変更等をAgent Coreの経験にするadapter/producerが不足している。

## Scope

- 概念設計と実装設計を一次情報としてdocsの契約を整合させる。
- Domain、Runtime、PersistenceまたはAdapterの必要箇所を修正する。
- 不要になった旧契約と後方互換処理を削除し、必要なmigrationを適用する。

## Out of scope

- この項目と無関係な振る舞いの変更。
- 数ターンの自動テストによる長期人格形成の合否判定。

## Implementation notes

- 対応ブランチ: `checklist/runtime-event-inputs`
- LLMは自然言語の意味判断と提案を担当し、RuntimeはID、時刻、所有権、権限、参照整合性を検証する。
- 既存データ構造を変更する項目では、冪等なPostgreSQL migrationで現行形式へ統一する。

## Acceptance criteria

- [x] specとdocsの責務・データ契約が整合している。
