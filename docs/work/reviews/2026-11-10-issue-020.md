## 指摘

### HIGH — C-06 / C-24 の必須 PostgreSQL 回帰テストが Runtime 経由でない

- 根拠: Issue の `Tests` は「Concern を含まない Agent Core Contextと完全Stateを分離して**通常Eventのproposalをcommit**」する PostgreSQL integration test を要求している。
- 現状: `tests/integration/persistence.test.ts:499-513` は `ContextBuilder.build` 後に、テスト自身が `source.state` を直接 `AgentStatePatchService.initial` へ渡して update を作り、`PostgresRuntimePersistence.commit` を直接呼ぶ。この経路は `PostgresAgentContextLoader.load` が返す `persistentState` と、`AgentRuntime.#execute` がそれを proposal に適用する箇所（`src/application/agent-runtime.ts:111-137`）を通らない。
- 影響: Context と完全State の実行時分離を取り違え、Runtime が `input.state` を更新基準としてしまう回帰を、この統合テストでは検出できない。受け入れ条件 C-06 / C-24 の検証が未達である。
- 修正候補: 下流（テスト）を修正する。PostgreSQL の `PostgresAgentContextLoader` + `PostgresRuntimePersistence` を `AgentRuntime.process`（または同等の通常 Event 実行経路）に接続し、Harness が Concern proposal を返すようにして、(1) Harness が受けた `input.state.concerns` が空、(2) commit 後の DB に既存 Concern と proposal で作成した Concern が共存する、を検証する。

## 確認済み

- C-23: `ContextBuilder` は Agent Core Context の `state.concerns` を空配列にし、ローダーは Context 構築前の完全Stateを `persistentState` として別途返す（`src/application/context-builder.ts:26-29`、`src/infrastructure/persistence/postgres-agent-context-loader.ts:132-158`）。
- C-24: Runtime は `persistentState` を Agent Core と Experience Integration に渡さず、Concern proposal の適用基準として使う（`src/application/agent-runtime.ts:111-140`）。この設計は一次仕様の「Runtime 専用完全 Persistent State」と一致する。
- 上流反映: `spec/personal-agent-implementation-design-v2.md:556` に C-23 の分離方針が反映済み。C-06 と C-24 を変更する決定は差分にない。
- Scope: `postgres-experience-integration.ts` の互換パースは Runtime 専用値を Experience Integration の判断入力へ残さないための付随変更であり、Issue の「Debug UI の判断入力へ混在させない」に整合する。Scope 外の要件変更は確認されなかった。
