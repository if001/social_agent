# Issue #036 レビュー

## 結果

初回レビューでは、16件上限だけでは最大長のConcern本文でtoken上限を超える点と、期限順の未検証を指摘した。

対応として、MemoryとConcernをレコード単位で選び、固定view全体を推定5,000 token以内に制限した。本文は切り詰めない。期限は過去、未指定、未来の順で、日時順に選ぶ。固定viewから外れたConcernがある場合は件数をモデルへ渡し、skillが`concern_list` / `concern_get`で補完できるようにした。

Targeted Concern commitに欠けていた`presented` Activityも追加し、close判定ではそれを状態変更として扱わないことを確認した。
