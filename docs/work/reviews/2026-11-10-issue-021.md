## 指摘

### HIGH — stale 期間が正の設計に定義されておらず、close の受け入れ条件を実装・検証できない

- 根拠: Issue 021 は Scope で「決めた stale 期間」を定めることを要求し、受け入れ条件でその設計が反映済みであるとしている（`issues/021-design-agentic-reflection-and-concern-decay.md:56-61, 98-100`）。しかし、一次仕様と FR-25 はいずれも「stale期間を超え」とするだけで、期間、設定の所在、あるいは「十分な取得・再検討機会」を満たす決定規則を定義していない（`spec/personal-agent-implementation-design-v2.md:745-747`、`docs/REQUIREMENTS.md:152`）。
- 影響: 022 は「021で決めた期間」を実装する前提であり（`issues/022-record-concern-activity-and-close-stale-concerns.md:42`）、baseline からいつ close 対象になるかを決定できない。テストの期待値も定まらない。
- 修正候補: 上流（一次仕様の具体化はユーザー承認が必要）または下流（設定値・既定値・測定時刻・再評価機会の算定を ADR / Requirements に定義）のいずれかを選ぶ。少なくとも 022 が参照できる決定論的な規則を正の文書へ置く。

### HIGH — Architecture の本文に一括Reflection前提の旧記述が残り、採用した対象別 Session 設計と矛盾する

- 根拠: 新しい ADR-7 / ADR-17 は対象別 Session、読み取りTool、完全State差分commit、Concern Activityを採用している（`docs/ARCHITECTURE.md:37,47`）。一方、同じ文書の Reflection 詳説は Event / Memory 各32件を一括入力する単一処理と reflection plan を規定し（`docs/ARCHITECTURE.md:167-169`）、Concern lifecycle も Activity / stale close を含まない旧規則のままである（`docs/ARCHITECTURE.md:116`）。これは C-25 §23 の対象別Reflector・Activity設計（`spec/personal-agent-implementation-design-v2.md:673,697-703,741-747`）と両立しない。
- 影響: 023 の実装者は同一Architectureから相反する実装方針を読める。Issue 021 の「Architectureへ反映済み」という受け入れ条件（`issues/021-design-agentic-reflection-and-concern-decay.md:99,146`）も未達である。
- 修正候補: 下流（`docs/ARCHITECTURE.md`）を新設計に合わせて更新または旧記述を明示的に廃止する。一次仕様の変更は不要。

### MEDIUM — C-06 を変更したという差分・受け入れ条件と、一次概念仕様の実態が一致しない

- 根拠: Issue 021 は C-06 に Activity、baseline、減衰を「一次文書へ反映」とし、差分も C-06 を MODIFIED と記載する（`issues/021-design-agentic-reflection-and-concern-decay.md:98,112`）。しかし C-06 の定義は Desire と Concern の区別だけであり（`spec/personal-agent-concept-design-restructured-v2.md:236`）、今回のActivity / baseline規則は実装仕様 §23.5 にのみ存在する（`spec/personal-agent-implementation-design-v2.md:741-747`）。
