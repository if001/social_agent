# Issue #018 実装レビュー

対象: `issues/018-experience-integration-retry-and-output-repair.md`、`main` との差分、概念設計 C-03 / C-16

## 指摘

### HIGH: 「変化なし」のprompt指示がRelationship/Mood schemaと矛盾している

`src/infrastructure/agent/experience-integration-harness.ts` は、Relationship と Mood について変化がない場合に「省略または空配列にします」と指示している。一方、`ExperienceIntegrationOutputSchema` では `relationship` は object の optional、`mood` は string の optional であり、いずれも空配列を受け付けない。

そのため、provider がこの指示どおり `relationship: []` または `mood: []` を返すと初回出力は検証に失敗する。修復呼び出しも同じsystem promptを使うため、同じ不正形式を繰り返してtraceが `failed` のままになる可能性がある。今回解消したMemoryIntentの必須field不足と同じ種類の運用障害を残す。

`memories` のみを空配列で表し、Relationship/Moodに変化がなければ各keyを**省略する**、と明示する必要がある。

**対応済み（2026-11-07）**：promptを「変化がなければ省略します」へ修正し、`memories` だけが空配列を用いることをunit testで固定した。

## 受入条件・整合性の確認

- 新形式snapshotは `result.toolExecutions` に保存され、`pending()` はその形式を `AgentRunResultSchema` へ復元する。
- 旧形式のtop-level `toolExecutions` もread-timeで補完しており、migrationを要しない。
- 初回のschema不適合時だけ `repair` を呼び、修復結果も不適合なら `fail` へ隔離する。Agent CoreのActionを再実行・巻戻ししないため、C-16のfailure isolationと整合する。
- Experience Integrationはcommit後のMemory/Mood/Relationshipの保存判断に留まり、個体化の経験を持続反映するC-03とも整合する。
- 初回commitとIntegration trace作成の間のcrash windowはIssue #018のout of scopeであり、本レビューの差分起因の指摘には含めない。

## テスト観点

追加テストは新旧snapshotの復元、1回だけの修復、修復不成功時のfailをカバーしている。上記HIGHを修正する際は、`relationship` / `mood` の空配列を禁止し、省略時だけ成功するprompt契約テストを追加すること。
