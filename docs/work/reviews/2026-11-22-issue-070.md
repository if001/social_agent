# Issue 070 レビュー

## 対象

- Issue: `issues/070-recover-discord-reply-chain-hop-in-memory.md`
- 実装差分: `main...issue/070-recover-discord-reply-chain-hop`
- 要件: FR-88、NFR-10
- 設計: ADR-21

## 確認結果

- Discord の送信成功後だけ、message ID をキーに action / correlation / hop / expiry を Bot process 内の Map に保存する。
- allowlist peer がその ID を参照して返信した時だけ、correlation を引き継ぎ hop を 1 増やす。human の返信では既存の causation 復元だけを維持し、hop は 0 のままである。
- Map miss と expiry 後は trace を使用しない。DB、Redis、Bot 間共有の経路は追加していない。
- 期限内の peer reply と expiry 後の reply を contract test で確認している。対象 test は 6 件すべて成功し、`pnpm typecheck` も成功した。

## 指摘

| 重大度 | 内容 | 根拠 | 対応候補 |
|---|---|---|---|
| MEDIUM | AC-070-2 と FR-88 の受理規則が食い違う。AC-070-2 は「allowlist 外…投稿は新規 ingress (`hop: 0`)」と読むことができるが、FR-88 は allowlist 外 Bot の Event を作らない。実装は FR-88 に従って allowlist 外 Bot を受理せず、`hop: 0` の ingress にしない。 | `issues/070-recover-discord-reply-chain-hop-in-memory.md` AC-070-2、`docs/REQUIREMENTS.md` FR-88、`src/infrastructure/ui/discord-adapter.ts` の受信除外条件 | Issue の AC-070-2 と FR-88 の「allowlist外投稿は新規 ingress」の文言を、allowlist 外 Bot は受理しない、owner human の返信・Map miss・期限切れ・reply先なしは新規 ingress、と明確化する。 |

## 指摘への対応

- MEDIUM #1 は実装を変えずに解消した。FR-88 と AC-070-2 を、allowlist外BotはEventを作らず、受理済みowner human投稿・Map miss・期限切れ・reply先なしだけを`hop: 0`の新規 ingressと明記する文言へ更新した。

CRITICAL / HIGH の指摘はない。
