## 主な確認点

### G3のMemoryIntent経路

上流の`spec/prediction-error-design.md`は、G3がMemoryを直接書き換えず、`remember`（MemoryIntent）をMainAgentへ渡し、MainAgentが採用・不採用を決めるとしている（C-66、8.4、12章）。

一方、`docs/REQUIREMENTS.md`のFR-58と`docs/ARCHITECTURE.md`のEvent説明は、G3もMemoryIntentをmemory-update Eventへ直接適用するように読める。実装時に「G3が直接memory-update Eventを発行する」と「MainAgentがG3のMemoryIntentを採否してから発行する」のどちらにするかを決める必要がある。

推奨は、上流どおり**G3 → MainAgent → memory-update Event**である。G3の仮説をMainAgentが採否することで、Memory更新の主体がMainAgentに残り、G3の誤った仮説が直接永続化されるのを防げる。

### テスト未実装

FR-48〜FR-64とAC-11〜AC-18は追加設計の要件であり、テストファイルはまだ存在しない。TEST_STRATEGYには予定ファイルを記載済みだが、trace_checkのWARN/INFOは実装まで残る。Release条件を満たすには、各Issueで対応するtestを追加する必要がある。
