# 変更分析: Issue 044 Drizzle runtime CRUD移行

## 対象

- 基準: `spec/personal-agent-implementation-design-v2.md` §9、`docs/REQUIREMENTS.md` NFR-7 / NFR-8 / NFR-11、`docs/ARCHITECTURE.md` ADR-8
- 変更: `issue/044-drizzle-runtime-crud` の未commit差分
- 除外: ユーザー作業中の `AGENT.md`、`scripts/start-all.sh`、`drizzle/issues/029-*`、`drizzle/issues/030-*`、既存の `docs/work/analyze/` 記録

## 結果

通常CRUDとtransactionは `RuntimeDatabase` / Drizzle schemaを通す形へ移行した。`Pool` を直接扱うapplication service、Tool adapter、Debug UI entry pointは残っていない。PostgreSQL固有SQLはrepository内のvector/hybrid ranking、lease claim、advisory lock、rate-window原子更新だけに限定した。

Reflectionについては、旧combined commit、Memory Formation/Reconciliationの通常Event選択・Resolution書込み、Concernの期限切れ閉鎖をDrizzle transactionへ置換した。固定Event窓のhybrid rankingとReconciliation候補順位付けだけは、NFR-11で許容されるRAG候補抽出としてrepository内に残る。

## 照合

| 要件 | 実装・検証 |
|---|---|
| NFR-7 | Event/Run/Reflection/Memory監査の通常書込みを型付きschema経由に統一。`tests/integration/persistence.test.ts` がReflection、Memory、Concern、Runtime監査を実DBで検証。 |
| NFR-8 | `RuntimeDatabase.transaction` 内でEvent transaction、Memory mutation、Reflection commitを確定。統合テストでrollbackと重複確定を確認。 |
| NFR-11 | `PostgresAgentLeaseRepository` と各repositoryへDB所有権を集約。Debug UI entry pointのPool直接操作を除去し、native SQLの所有者一覧をIssue #044へ記録。 |

## 機械検査

`python3 .agents/skills/spec-analyze/scripts/trace_check.py --root .` は ERROR 0件、既存要件のテスト参照不足に関する WARN 7件を報告した。今回の変更で追加されたERRORや要件IDの不整合はない。

## 判断

- `g3_tasks.plan` の過去snapshotと実DBの差はruntime query tableで局所化されている。schema cutoverを伴う履歴修復はIssue #044のCRUD境界変更から分離する。
- Debug UIの監査projectionは読取り専用repositoryが所有する。entry pointからの任意SQL実行は許可しない。
