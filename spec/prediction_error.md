# 会話Agentの階層的予測・予測誤差 概念設計

## 1. 目的と前提

- 本システムは、特定のユーザーと1対1でテキスト会話するAgentに、予測と予測誤差に基づく主観的な認知処理を与える。
- LLMの重みは更新しない。予測・解釈・誤差評価にはLLMを使い、経験に基づく変化は主として記憶・信念の更新によって実現する。
- LLMが持つ知識は一般知識・常識として扱う。Agent固有の経験、自己像、ユーザー理解、共有知識は外部記憶に保持する。
- Agentはユーザーに迎合することを目的としない。記憶違い、勘違い、誤った原因帰属、信念の維持や反発も起こり得る。
- 予測・誤差評価と、記憶更新・感情・動機・行動決定は分離する。行動決定は初期には単純な実装とし、拡張可能にする。
- 記憶は基本的に種類別のデータとしてDBに保持し、必要に応じてRAGなどで検索・取得する。

## 2. 認知モデル

予測対象は概念的に6階層とし、処理単位は3グループとする。

| ID | 処理グループ | 階層 | 予測対象 |
|---|---|---|---|
| - | G1：言語形式 | L1 | 語彙、文法、表記、口調、言い回しなど |
| - | G2：意味・会話行為 | L2–L3 | 発言の意味・命題、質問、依頼、同意、拒否など |
| - | G3：認知・対人モデル | L4–L6 | 意図・目標、知識・信念、個人の傾向、Agentとの関係 |

- グループは必ずしも全て毎回実行しない。複数グループの並列処理、あるグループの誤差を契機とした追加処理、上位の解釈による下位の解釈の見直しを許容する。
- 起動判断には、予測との不一致だけでなく、不確実性、会話上の重要性、目標との関連性を用いる。G3は誤差発生後だけでなく、事前に深い予測が必要な場合にも実行できる。

## 3. 記憶と認知状態

### 3.1 永続記憶

- 永続記憶はDBに保持する。各記憶は必要なときに検索し、関連部分のみ処理へ渡す。
- 永続記憶の種別は次の6種とする。

| 記憶の種類 | 保持する情報 |
|---|---|
| Episodic / Conversation Memory | 過去の発言、出来事、状況、時刻、元の発言への参照 |
| User Model | ユーザーについての知識、信念、嗜好、習慣、目標に関するAgentの認識 |
| Agent Self-Model | Agent自身の自己概念、知識、過去の行動、説明、約束、目標 |
| Common Ground | 両者で何を共有済みと認識しているか、相手が何を知っていると考えるか |
| Relationship Model | 当該ユーザーとAgentの間で形成された期待、関係の傾向、行き違い、共有経験 |
| Goal / Task Model | ユーザー・Agent・両者の進行中の目標、状態、未解決事項 |

- これらは論理的な記憶種別であり、物理的なDB・テーブルの分割方法は詳細設計で決める。各情報には必要に応じて、主体、内容、根拠、時点、有効性、確信の程度、参照先を保持する。観測された発言と、それに対するAgentの解釈・推測は区別する。
- 記憶は客観的に正しいことを保証しない。Agentは記憶を誤って再構成したり、矛盾した信念を保持したりできる。誤差が検出されても記憶の修正は必須ではない。

### 3.2 初期記憶

- 会話開始前に、Agent固有の初期自己概念、信念・価値観、行動傾向、架空の自伝的経験をDBに投入できる。初期記憶も通常の記憶と同様に検索・更新の対象とする。
- 初期記憶は単なる固定の人格指示ではなく、Agentが自身の経験・信念として参照する情報である。
- 初期の架空経験と、起動後に実際の会話で得た経験は、管理上は由来を区別する。
- 実際には存在しないユーザーとの共有経験を、既成事実として初期設定しない。
- 初期記憶の定義ファイルを使う場合でも、それはDBへの投入元とし、起動後の変更を初期値で上書きしない。

### 3.3 一時状態

- 一時状態は次の3種とする。

| 状態 | 役割 |
|---|---|
| Working State | 現在の会話文脈、未解決事項、現在参照中の記憶 |
| Prediction State | 観測前の予測候補、予測根拠、対象、観測との対応 |
| Processing State | 実行中・保留中の処理、対象ターン、追加検索、再推論の状況 |

- 一時状態と永続記憶は区別する。重要な予測結果や解釈を永続化する場合も、その由来と時点を保持する。

## 4. グループ別の情報取得

- グループごとの入力と取得情報は次のとおり。

| グループ | 主な入力 | 必要に応じて取得する情報 |
|---|---|---|
| G1 | 直近の発言、言語、短期文脈 | ユーザーやAgentの言い回し・文体の傾向 |
| G2 | 直近の会話、現在の話題、会話行為、未解決の質問 | 目標・タスク、関連する会話記憶、共有済みの情報 |
| G3 | 現在の発言と解釈、関連する既存の信念 | User Model、Agent Self-Model、Common Ground、Relationship Model、エピソード、目標 |

- 各グループは独立した記憶を複製して保持するのではなく、共通の記憶群から目的に応じて取得する。G3では複数の記憶種別を横断した検索や、根拠・矛盾の照合を行い得る。深い処理ほど必ず遅いとは限らないが、追加取得や再推論のために応答後まで処理が続く場合がある。

## 5. 予測・解釈・予測誤差

### 5.1 予測

- 予測は、次の返答を文字列として一つに確定するものではない。各グループが対象とする特徴や意味について、**複数の可能性と、その相対的な期待の強さ**を表現する。
  - G1：文体、語彙、言語的特徴などの期待。同時成立する特徴を許容する。
  - G2：肯定、否定、保留、質問、話題転換など、意味・会話行為の候補。
  - G3：相手の意図・知識・信念・個人傾向に関する仮説と、それを支持・反証し得る観測可能な兆候。

- 候補と説明は自然言語で保持し、期待度は当初 `very_high / high / medium / low / very_low` などの離散値で扱う。候補外の応答も許容する。
- LLMが直接出力した数値を、校正済み確率として扱わない。

### 5.2 観測と解釈

- ユーザーの実際の発言（観測）と、Agentがその発言をどう理解したか（解釈）を区別する。解釈は誤り得る。G2は意味や会話行為を解釈し、G3は必要に応じて潜在的な意図・信念や自己の記憶との関係を推論する。

### 5.3 誤差評価

- 各グループは、観測前に確定した予測と、観測・解釈を照合する。結果として次の項目を表す。

| 項目 | 内容 |
|---|---|
| `match` | 主要候補に一致／代替候補に一致／想定外／評価不能 |
| `surprise` | 主観的な意外性（`none / low / medium / high / unknown`） |
| `difference` | どの特徴、意味、仮説が予測と異なったかという自然言語の説明 |
| `interpretation` | Agentが実際の発言をどう受け取ったか |
| `uncertainty` | 解釈の不確実性 |
| `attribution` | 不一致の原因についての仮説。判断できない場合は保留 |

- 「差異の内容」「意外性」「解釈の不確実性」は別概念として扱う。想定内の低期待候補が実現した場合と、想定した会話の枠組み自体が成立しなかった場合を区別する。G3では、仮説に対する支持・反証・判断不能も評価する。
- 当初は自然言語と離散値の組み合わせを採用し、確率値や数値的なスコアは必須としない。予測能力を後から検証するための客観的な評価指標は、Agentの主観的な誤差とは別に設計できる。

## 6. 処理の流れと時間

UI 層は入力を Queue 層に積む。Agent は Queue から1件ずつ取り出す。

- 会話ターンと内部時間ステップ（Agent内の処理）は独立して進行する。
  1. Agentは、その時点で利用可能な文脈・記憶から必要なグループの**事前予測**を形成・保持する。
  2. ユーザーの発言を観測する。
  3. G1・G2など必要なグループが観測を解釈し、事前予測との差異を評価する。
  4. Agentの意思決定モジュールが応答を選択し、ユーザーに返答する。
  5. 必要であれば、返答後も内部ステップでG3などが追加記憶を検索し、解釈・原因帰属・信念更新候補を検討する。
  6. 内部処理の結果に応じて、記憶を維持・更新し、またはAgentが追加で発言することがある。発言するかどうかは意思決定モジュールが決める。

- Agent は、ユーザー入力に対して応答を返す。

上記は代表的な流れであり、G3を事前または応答前に実行することもできる。新たなユーザー入力がなくても、内部時間ステップにより保留処理や再検討を進められる。

- プロセスを再起動したとき、Agent は直近の会話ログから文脈を戻し、同じ会話を続ける。

- ターンとは、ユーザーの入力から Agent の応答までの1サイクルを指す。応答は1回以上でよい。返答後の処理はターンとは別に進む。

- **時点の区別**：観測後に検索・生成した解釈や仮説は、観測前に存在した予測として扱わない。遅延処理でも、事前予測、参照した文脈の時点、観測後の推論を区別する。

## 7. モジュール境界

- Agent 内のモジュールと責務は次のとおり。

| モジュール | 責務 |
|---|---|
| Memory / Retrieval | 種類別記憶の保持・検索・取得 |
| Prediction | グループごとの事前予測の生成・保持 |
| Interpretation | 観測された発言の意味・意図などの解釈 |
| Error Evaluation | 予測と観測・解釈の比較、意外性、差異、原因仮説の出力 |
| Memory / Belief Update | 新しい経験の保存、信念の維持・更新・再解釈 |
| Decision | 応答、追加発言、保留、記憶更新の扱いなどの最終判断 |
| Scheduler / Processing | 会話ターンとは独立した内部処理の起動・継続・保留 |

- 予測誤差は、記憶更新だけでなく、驚き、疑問、反発、自分の記憶への疑念などの入力になり得る。ただし、感情・動機・行動は別モジュールの責務とする。誤差の存在は、信念修正やユーザーへの迎合を強制しない。

- UI 層は、ユーザー入力を受け取って Event Dispatcher に渡す。応答を表示する。
- Discord bot は、指定した1つのチャンネルでメンションと自分の発言への返信に応答する。内部状態を投稿しない。
- Queue 層は、入力を到着順に保持し、Agent に1件ずつ渡す。UI は完了を待たない。
- Queue はプロセス内のメモリに保持する。再起動すると未処理の入力は失われる。
- Queue 層は、ユーザー入力だけを保持する。内部処理タスクは Scheduler が管理する。
- Queue 層は、入力を到着順に Agent に渡す。準備が済むまで次の入力を渡さない。
- Queue は作業項目を50件まで保持する。超えたときは最も古い入力から捨てる。
- 外部サービスが失敗したとき、Agent はエラーを表示し、次の入力を受け付ける。失敗したターンの記憶は保存しない。
- CLI はターンと内部ステップの区切りごとに、予測、誤差評価、記憶更新を表示する。
- Agent は予測、観測、誤差評価を記録し、後から集計できるようにする。

## 8. 後続設計で具体化する事項

- 本書では概念の境界を定義し、実装上の詳細は固定しない。要件定義・詳細設計では、DBスキーマ、RAGの検索・関連度判定、各処理の入出力スキーマ、グループ起動条件、内部ステップの実行方針、記憶更新規則、初期記憶の生成・投入方法、主観的誤差と客観的性能評価の方法を具体化する。


# 階層別の文脈構成とAgent型推論 — 概念設計

## 1. 目的と前提

- 本書は、1対1のチャットAgentにおける階層別の文脈構成、記憶検索、および反復推論の方針を定める。予測・予測誤差はLLMによって処理し、LLMの重みは更新しない。学習に相当する変化は、主としてAgentの永続記憶・信念の更新によって生じる。
- Agentは独自の経験・信念・解釈を持ち、記憶違いや勘違いをする場合がある。予測・誤差評価・記憶更新・意思決定は別の責務とし、予測結果が直接発話を決定することはない。

## 2. 認知階層と処理グループ

6階層は**予測対象**、3グループは**実行のまとまり**を表す。

| ID | グループ | 階層 | 予測対象 | 基本的な処理 |
|---|---|---|---|---|
| - | G1 言語形式 | L1 | 語彙、文法、表記、言い回し | 単純なLLM処理 |
| - | G2 意味・会話行為 | L2 | 意味・命題 | LLM処理、必要時に記憶取得 |
| - | G2 意味・会話行為 | L3 | 質問、同意、拒否などの会話行為 | LLM処理、必要時に記憶取得 |
| - | G3 認知・対人モデル | L4 | 相手の意図・目標 | 記憶検索を伴うAgent型推論 |
| - | G3 認知・対人モデル | L5 | 相手の知識・信念 | 記憶検索を伴うAgent型推論 |
| - | G3 認知・対人モデル | L6 | 個人の傾向・関係性・共有認識 | 記憶検索を伴うAgent型推論 |

- 各階層は独立して完結するとは限らず、他階層の推定結果を参照できる。すべての階層を毎ターン起動する必要はない。

## 3. 永続記憶と取得対象

- 記憶は原則としてDBに保持し、RAGなどの検索手段を介して取得する。次の6種類を区別する。

| ID | 記憶 | 内容 |
|---|---|---|
| M1 | Episodic Memory | 過去の会話、経験、出来事 |
| M2 | User Model | ユーザーの知識、信念、嗜好、傾向 |
| M3 | Agent Self-Model | Agent自身の経験、自己認識、行為、約束 |
| M4 | Common Ground | 両者が共有しているとAgentが考える知識 |
| M5 | Relationship Model | ユーザーとAgentの関係、相互の期待 |
| M6 | Goal / Task Model | 目標、意図、進行中のタスク |

- 初期状態では、Agent固有の自己概念・信念・架空の自伝的記憶などをDBに投入できる。ユーザーとの実際の共有経験は対話後の観測から形成する。
- 取得した記憶はAgentの主観的な情報であり、必ずしも正確とは限らない。

## 4. 階層別の文脈構成

各階層は、共通のDBから**それぞれの予測目的に必要な情報を選択して文脈を構成する**。以下は優先的な取得先であり、固定の検索順序やアクセス制限ではない。

| ID | 階層 | 基本入力 | 主な記憶取得先 |
|---|---|---|---|
| - | L1 | 入力発言、直近の会話 | 原則不要。必要時にM2・M5 |
| - | L2 | 入力発言、話題、会話状態 | 必要時にM1・M4・M6 |
| - | L3 | 直前のやり取り、未解決の質問・依頼 | 主にM6、必要時にM1・M4 |
| - | L4 | L2・L3の結果、進行中の目標 | M2・M6、必要時にM1 |
| - | L5 | L2・L4の結果、知識に関する仮説 | M1・M2・M4、必要時にM3 |
| - | L6 | L3〜L5の結果、関係性の状況 | M1・M2・M3・M4・M5 |

- 取得先は優先であり、固定の検索順序やアクセス制限ではない。
- 文脈の構成は単一のベクトル検索に限定しない。例えばL6では、共有知識を調べた後、その根拠となる会話やAgent自身の過去の行為を追加検索することがある。

## 5. G3のAgent型推論

- G3では、L4・L5・L6にそれぞれ専門的な**予測目的・検索方針・出力**を定義する。
- 必要な記憶を段階的に取得するため、ReAct型の「推論 → Tool使用 → 観測 → 推論」の反復を許容する。

| ID | 階層 | 主な問い | 主な検索 |
|---|---|---|---|
| - | L4 | 相手は何を達成したいか | 目標、ユーザー像、関連エピソード |
| - | L5 | 相手は何を知り、何を信じているか | 知識モデル、共有知識、根拠となる発言 |
| - | L6 | なぜ自分にその態度を取り、どのような関係・共有認識があるか | 関係性、共有知識、自己記憶、過去の経験 |

- 実装初期は**G3を1つのAgent**とし、処理対象の階層を指定する構成でよい。必要に応じてL4・L5・L6を独立したSub Agentへ分離できるよう責務を定義する。各階層を毎回個別に起動する必要はない。

### 記憶検索Toolの考え方

- Toolは記憶DBの内部構造に強く依存させず、検索目的に応じたインターフェースとする。例を次に示す。

```typescript
searchMemories(query, memoryTypes)
getRelatedEpisodes(memoryId)
getBeliefs(subject, topic)
getSharedKnowledge(topic)
getAgentExperiences(topic)
getRelationshipContext(topic)
```

- Toolは階層間で共有してよいが、参照可能なToolや優先検索先は階層の目的に応じて変える。
- 階層間では、必要に応じて仮説・期待・不確実性・根拠参照を引き継ぎ、検索結果全体の無条件な共有は避ける。

### 反復推論の終了

- 次のいずれかに該当する場合、検索・推論を終了できる。

- 予測や解釈に十分な材料を得た。
- 追加検索による新情報が乏しい。
- 検索回数・処理資源の上限に達した。
- 情報不足を明示した結果を返せる。

- すべての記憶を確認することは要求しない。検索不足や誤った記憶に基づく主観的解釈も許容する。

## 6. 会話ターンとAgent内部時間

- Agentは、ユーザーとの**会話ターン**とは独立した**内部処理ステップ**を持つ。ユーザー入力だけでなく、内部Taskの完了やSchedulerによる起動も処理の契機となる。

| ID | 概念 | 役割 |
|---|---|---|
| - | Conversation Event | ユーザーまたはAgentの発言。外部から観測できる出来事 |
| - | Internal Step | 予測、誤差評価、記憶検索、再推論などの内部処理 |
| - | Agent Action | 発話、記憶更新、追加Taskの登録、何もしない等の選択 |

- 会話イベントと内部ステップは1対1ではない。1つの発言から複数の内部処理が発生し、ユーザーからの新しい入力がなくても内部処理は継続できる。

### 6.1 通常の応答と時差式の処理

- 通常の処理では、入力を受けてG1・G2を中心に予測誤差を評価し、Main Agentが返答する。必要な場合は返答前にG3も起動できる。

- 通常の応答の流れは次のとおり。

```text
User → Event Dispatcher → G1/G2（必要時G3）
     → Main Agentの意思決定 → Agentの返答
```

- 時差式の処理では、まず応答し、その後にG3の深い推論を実施できる。G3の結果は、追加発話を直接発生させず、Main Agentによる新たな意思決定に渡す。

- 時差式の処理の流れは次のとおり。

```text
User → Event Dispatcher → G1/G2 → Main Agent → Agentの返答
                             │
                             └→ SchedulerにG3 Taskを登録
                                        ↓
                                G3（L4～L6、ReAct+記憶Tool）
                                        ↓
                                  内部処理完了Event
                                        ↓
                                 Main Agentの再判断
                                        ↓
                              何もしない / 記憶更新 / 追加発話
```

- G3は常に遅延させるものではなく、応答内容の決定に必要なら返答前に実行する。G3の一部だけを起動することもできる。

### 6.2 Event DispatcherとScheduler

- **Event Dispatcher** は、ユーザー入力、Agentの発話、内部Taskの完了などを受け取り、処理の起点を作る。
- **Scheduler** は、内部Taskの登録、実行、保留、再開、完了を管理する。会話ターンと独立してTaskを進行させる。
- **Prediction Controller** は、起動する処理グループ・階層と実行タイミングを選択し、結果を統合する。
- **Main Agent** は、処理結果を受けて実際の行動を決定する。追加発話するかどうかもここで判断する。
- 初期実装ではEvent DispatcherとSchedulerを一体化してよい。将来は、会話由来ではない振り返りや再調査などの自律Taskにも拡張できる。

### 6.3 内部Taskの状態

- 遅延・再開ができるよう、Taskは少なくとも**発生元イベント、対象階層、処理状態、予測への参照、文脈の基準時点**に紐づける。

- 内部Taskの例を次に示す。

```yaml
id: task_102
source_event: user_message_10
type: deeper_inference
target_layers: [L4, L6]
prior_prediction_ref: prediction_09  # 存在する場合
context_snapshot_ref: context_10
status: pending
```

- 内部Taskの完了は新しいEventとなり、次の意思決定や内部Taskを発生させられる。実際の処理基盤は、イベント駆動またはTaskキュー等で実現する。

### 6.4 予測の時点と遅延処理の整合性

- **予測誤差は、観測前に確定した予測と実際の観測を比較して求める。** 観測後にG3が新たに作った仮説は事後推論であり、過去の事前予測として扱わない。
- 観測前にG3の予測が保存されていれば、その誤差評価を遅れて実施できる。
- 遅延Taskは発生元の会話時点を参照できるようにし、追加の記憶検索時には新しい情報と当時の情報を区別する。追加発話の直前には現在の会話状態を確認し、古い推論結果をそのまま発話するかどうかをMain Agentが判断する。主観的な誤認やタイミングの悪い反応自体はAgentの設計上許容する。

## 7. 責務の境界

- 責務の境界は次のとおりとする。

- **Event Dispatcher / Scheduler:** 会話・内部イベントの受信と内部Taskの進行管理。
- **Prediction Controller:** 処理グループ・階層の起動、実行タイミング、結果の統合。
- **Context Builder / Retrieval:** 階層の目的に応じた文脈構成と記憶検索。
- **G1〜G3:** 予測、観測の解釈、階層別の予測誤差・仮説の生成。
- **Memory Management:** 記憶の保持・検索・更新。予測誤差を受けても必ず修正するとは限らない。
- **Main Agent:** 内部状態を踏まえた意思決定・発話。予測結果に従う義務はない。

- 予測は単一の文字列ではなく、自然言語による候補群と定性的な期待度を基本とする。誤差は不一致の内容を自然言語で表し、必要に応じて離散的な強度・不確実性を付ける。厳密な数値確率は必須としない。

## 8. 後続設計で具体化する事項

- 本概念設計では、DB製品・スキーマ、検索ランキング、具体的なTool引数、LLMモデル、ReActのステップ上限、起動判定の閾値、Schedulerの実行方式・Task優先順位・発話判断基準、Agent間通信プロトコルなどは固定しない。要件定義と詳細設計で具体化する。
